The signal

01 / diagnosis

Primary problem: work happens too often, on the UI thread, or inside global input callbacks.

Do not start with: geometry math. It is bounded and action-only.

Start with: measurement, duplicate work removal, and event coalescing.

Do first

02 / low risk

Instrument the hot paths

P0

Safe / required before tuning

Measure startup, settings saves, stash polling, hook duration, preview capture, placement latency, allocations, and UI stalls.

Exit condition
Baseline p50 and p95 values on idle, drag, radial, preview, settings, stash, and placement flows. No per-mouse-event logging.

Remove duplicate stash work

P1

MainWindow / WindowStashService

The 80 ms timer prunes stale windows, then reveal logic prunes them again. Each check can inspect HWND, process, title, class, and executable path.

Plan
  • Run one maintenance pass per tick.
  • Reuse the cleaned runtime set for reveal.
  • Stop polling when no stash records exist.

Cut idle mouse-hook work

P1

DragSnapService / global input

Every global mouse move is parsed and can enter the WPF dispatcher, even when drag snapping is disabled or no drag is active.

Plan
  • Fast-path idle moves before marshaling.
  • Keep only the newest pending drag point.
  • Preserve button-down and button-up ordering.
  • Resample on release.

Cache process facts per scan

P1

WindowPolicy / WindowQuery

Window enumeration can resolve the same process path and name repeatedly for multi-window applications.

Safety rule
Use an enumeration-scoped cache keyed by PID. Do not keep a long-lived PID cache. Preserve elevated-process fallbacks and z-order.

Reuse one action plan

P1

WindowActionService

Action execution authorizes and resolves the target more than once, then performs another monitor lookup.

Safety rule
Carry policy, current frame, monitor snapshot, target frame, work area, and limits through one operation. Keep one final validity and actual-frame check.

Remove duplicate refresh passes

P2

SettingsWindow

Startup and appearance changes reapply themes and radial controls more than once. Unrelated slider changes refresh unrelated controls.

Plan
Make one method own each state transition. Update only the changed domain, paired input, label, swatch, or surface.

Do later

03 / measured risk

Coalesce settings saves

P1

Slider changes currently serialize and write the complete settings file synchronously. Keep in-memory values and live previews immediate. Debounce only durable writes.

Flush points
Focus loss, navigation, reset, close, shutdown, and explicit discrete changes. Keep atomic replacement and error reporting.

Fix radial double sampling

P2

The overlay has both a 20 ms cursor timer and WPF mouse-move selection. Consolidate them only after edge and keyboard behavior is verified.

Defer or reuse overlays

P2

Radial and preview windows are created during repeated interactions. Defer preview creation until needed. Consider hide/reset reuse after lifecycle tests.

Profile screen capture

P2

Preview capture is synchronous and covers the full work area. Profile 4K and mixed-DPI displays before changing capture size or threading.

Hard rule
Any asynchronous bitmap must be rejected if its monitor, DPI, work area, or interaction generation is stale.

Replace placement sleeps

P3

Window placement can block the WPF dispatcher with repeated sleeps and native polling. This has the largest potential payoff and the highest regression risk.

Do not break
Keep the double SetWindowPlacement pattern, async placement flags, final frame verification, DPI behavior, focus, z-order, and a bounded timeout. Consider SetWinEventHook plus a timeout state machine.

Regression gates

05 / mandatory
01

Visual output stays identical: geometry, blur, shadow, opacity, theme, easing, and timing.

02

Input stays complete: trigger, keybind, drag, release, radial pointer selection, keyboard selection.

03

Window state stays correct: focus, z-order, activation, minimized/maximized behavior, elevated apps, and exact final frame.

04

Persistence stays durable: restart, stash recovery, closed windows, reused HWNDs, save failure, and shutdown.

05

Desktop matrix passes: 100%, 125%, 150%, 200%, negative coordinates, multiple monitors, mixed DPI, normal and high-polling mice.
